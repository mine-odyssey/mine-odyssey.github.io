        05 / The benchmark

        Agent framework

        Read the framework description

        we develop a programmable control interface that combines API-based player control with keyboard and mouse input.

        The in-game map provides a top-down view of the explored environment and supports panning, zooming or searching to inspect different areas.

        The agent uses these tools through Bash, either executing individual operations or composing multiple operations within a single Bash tool call with shell commands or Python scripts.

        An independent evaluator is used to verify arrivals by comparing the player's position with the annotated waypoint coordinates. It samples the client player position at 1 Hz throughout execution, including during model inference.

        The client uses an in-game presentation view and native map of Copacabana. The animation illustrates information flow; the verifier samples positions independently throughout execution, including during model inference.

        Model / effort

        Success Rate (SR)

        Fraction of tasks completed by visiting all required stops in order and submitting an accepted claim_done.

        Checkpoint Coverage (CC)

        Average fraction of ordered intermediate stops reached, measuring partial progress.

        Success weighted by Path Length (SPL)

        Successful completion weighted by route efficiency; shorter successful routes receive higher scores.

        Path Length (PL)

        Average full-episode 3D distance across all 180 tasks, including failures, sampled at approximately 1 Hz.

        Average turns

        Average number of agent turns per task, excluding automatic history-summary responses.

        Main results on 180 tasks, with success rates broken down by 125 outdoor and 55 indoor tasks. SR, CC, and SPL are percentages; PL is the mean sampled 3D distance over all tasks.

        07 / Analysis

        Case studies

        White House · Plaza Hotel · Ueno Park
        Recorded routes, original observations and agent programs.

        In both cases, Astra redirects its search and follows an alternative route to the target, while the unsuccessful models continues exploring within the same local region.

        Each route unfolds in its recorded order, normalized to the same animation length. Pauses are omitted; playback does not compare real-world running times or speeds. S / E mark the recorded endpoints; gold stars mark targets.

        Together, these cases show how agents use programming to turn visual map information into explicit coordinates and individual movement commands into reusable action sequences.
